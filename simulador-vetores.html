Heap 

    

    

      Sobre este modelo (simplificações)
      
    
        
  • Endereços fictícios: pilha a partir de 0x1000 e heap a partir de 0x8000. As variáveis ficam em ordem crescente; numa máquina real a pilha cresce para endereços menores e o compilador escolhe a ordem.
    • 
        
  • O compilador reserva espaço para todas as variáveis locais da função de uma vez; quando um bloco termina, o nome sai de escopo, mas o espaço continua lá.
    • 
        
  • Em C e C++, um vetor local fica inteiro na pilha. Em Java e C#, a variável guarda só a referência (4 bytes em Java com referências comprimidas, 8 bytes em C#) e o vetor é um objeto no heap.
    • 
        
  • Objetos no heap: 12 bytes de cabeçalho + 4 bytes de length, e depois os elementos (o tamanho exato do cabeçalho varia entre máquinas virtuais). Em C#, int[,] guarda também o número de linhas e de colunas.
    • 
        
  • Java não tem matriz contígua: int[][] é um vetor de referências para vetores-linha. C# tem as duas formas: int[,] (um bloco só) e int[][] (como em Java).
    • 
        
  • O coletor de lixo não é simulado: objetos sem referência aparecem esmaecidos.

Como escrever

      
Escreva só o corpo do programa, numa sintaxe comum às quatro linguagens (estilo C). O simulador gera o programa completo em C, C++, Java ou C#. Um comando por linha.

      
    
        
  • Tipos: int, double, char, float, short, long
    • 
        
  • Vetor: int v[5]; ou int v[5] = {3, 1, 4}; ou int v[] = {3, 1, 4};
    • 
        
  • Matriz: int m[2][3]; ou int m[2][3] = {{1, 2, 3}, {4, 5, 6}};
    • 
        
  • Acesso: v[i] = v[i] + 1; e m[i][j] = 0; (em C# int[,] vira m[i, j])
    • 
        
  • Atribuições: =, +=, -=, *=, /=, i++, i--
    • 
        
  • Condições: < <= > >= == !=, &&, ||, !
    • 
        
  • for (int i = 0; i < 5; i++) { … }
    • 
        
  • while (cond) { … } e if (cond) { … } else { … } (as chaves são obrigatórias)
    • 
        
  • Saída: print("v[", i, "] = ", v[i]);
    • 
        
  • Comentários: // texto
    • 
      

      
Limites do simulador: até 40 elementos por vetor, matrizes até 8 × 8 e 6 registradores.
