      Sobre este modelo (simplificações)
      
    
        
  • Endereços fictícios a partir de 0x1000; as variáveis são colocadas em ordem crescente. Em máquinas reais a pilha costuma crescer para endereços menores e a ordem é escolhida pelo compilador.
    • 
        
  • Cada variável é alinhada a um endereço múltiplo do seu tamanho, como fazem os compiladores C/C++ em x86-64.
    • 
        
  • A CPU tem 4 registradores genéricos (R0–R3) e uma ULA. Uma CPU real tem mais registradores e o compilador pode otimizar, guardando variáveis só em registradores.
    • 
        
  • Em Java e C#, as variáveis locais ficam no quadro (frame) do método na pilha da máquina virtual; a visão byte a byte aqui é conceitual. Em Java/C#, char tem 2 bytes (UTF-16).
    • 
        
  • Saída de números reais: C usa %f (6 casas), C++ mostra até 6 algarismos significativos, Java e C# mostram a representação mais curta. Em C#, a cultura pt-BR do Windows usaria vírgula decimal; aqui usamos ponto.

Como escrever

      
Escreva só o corpo do programa, numa sintaxe comum às quatro linguagens. O simulador gera o programa completo em C, C++, Java ou C#. Um comando por linha.

      
    
        
  • Tipos: char, short, int, long, float, double
    • 
        
  • Declarar: int a; ou int a = 5;
    • 
        
  • Atribuir: a = b * 2 + 1;
    • 
        
  • Operadores: + - * / %, parênteses e cast: (double) a / b
    • 
        
  • Literais: 42, 3.14, 2.5f, 'A'
    • 
        
  • Mostrar na tela: print("Soma: ", a + b); — vira printf, cout, System.out.println ou Console.WriteLine
    • 
        
  • Comentários: // texto (também no fim da linha)
    • 
      

      
Erros que só uma das linguagens aponta (por exemplo, usar variável sem valor em Java/C#) aparecem quando você troca a linguagem.
